# 0003: ZIO 2 as effect and runtime system

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-10-28 |
| Decided by | Philippe |

## Context

The platform needs concurrent processing (workers, polling the job table), resource safety (DB connections, file streams, object storage), structured error handling and dependency injection for wiring the modules in `app`. Blocking Java libraries (JDBC, Flowable) must be integrated. One person must be able to keep an overview of the code over the long term.

## Decision

ZIO 2 (currently `2.1.27`) is the only effect and runtime system, complemented by zio-config `4.1.0`, zio-logging `2.5.3` and ZIO Test. Effects are typed concretely as `ZIO[R, E, A]`; tagless-final abstractions (`F[_]`) are not used.

## Alternatives considered

| Criterion | Chosen: ZIO 2 | Typelevel (Cats Effect, http4s, Doobie) | Direct style (e.g. Ox) | Pekko |
|---|---|---|---|---|
| Error channel | Typed `E` in the effect type | `Throwable`, business errors via `Either` | Exceptions / `Either` | Exceptions, supervision |
| Dependency injection | `ZLayer`, built in | Manual / Resource | Manual | Manual / extensions |
| Configuration, logging, testing | Own modules from a single source | Separate libraries | Libraries freely chosen | Own modules |
| Learning curve | Medium | High (type classes, tagless final) | Low | Medium (actor model) |
| HTTP integration | ZIO HTTP, Tapir (0013) | http4s | Tapir with Netty/Loom | Pekko HTTP |
| Maturity for Scala 3 | High | High | Young, API still changing | High, focus on actors |
| Blocking Java APIs | `ZIO.attemptBlocking` | `IO.blocking` | Direct call on virtual threads | Dispatcher |

## Consequences

### Positive

- One consistent ecosystem: runtime, configuration, logging, testing, streams.
- Business errors are visible in the type and must be handled.
- `ZLayer` makes the wiring in `app` explicit and testable.
- Concrete types instead of `F[_]` keep signatures readable, also for AI assistance.

### Negative / Cost

- Lock-in to one ecosystem; Typelevel libraries (Doobie, http4s, fs2) are ruled out or usable only via interop.
- ZIO ecosystem modules differ in maturity and release cadence (see 0012: `magnumzio` only as a milestone).
- Larger runtime framework than direct style; stack traces are harder to read.
- Learning curve for fiber semantics, interruption and layer construction.

## Follow-ups

- Guardrail: no mixing with Cats Effect; no tagless-final abstractions.
- Every blocking Java API (JDBC, Flowable, file system) is wrapped with `ZIO.attemptBlocking`.
- Library selection is guided by ZIO integration (Tapir ZIO HTTP, zio-json).
- Define an error hierarchy per module in `*-api` as an ADT.
- Ruled out: http4s, Doobie, fs2, Pekko actors.

## Reversibility

**high**: ZIO runs through the signatures of all modules, the tests and the wiring. A switch would affect practically the entire codebase. Pure domain logic (e.g. `Lifecycle.scala`) is effect-free and would remain.
